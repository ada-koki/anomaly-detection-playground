# CI とデータの取り扱い

このリポジトリは CPU 優先のベンチマーク実験用であると同時に、公開リポジトリとして
「データ・重み・秘密情報を誤って公開しない」ことを重視している。本ドキュメントは
次の 4 点をまとめる。

1. CI が実行する内容と、外部データを使わない理由
2. 実データを使う長時間検証の進め方（CI の外）
3. 第三者データ・重みの権利とライセンス確認手順
4. コミット前チェック

## 1. CI が実行する内容

ワークフローは [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) にある。
`push` と `pull_request` の全ブランチで、`ubuntu-latest` と Python 3.11 / 3.13 の
matrix で実行する。

手順は次のとおり。

1. `python -m compileall -q adbench scripts tests`（構文検査）
2. `python -m unittest discover -s tests -v`（ユニットテスト）
3. `python scripts/run_anomalib.py --help`（CLI のスモークテスト）
4. `python scripts/check_repo_safety.py`（追跡ファイル全体の安全性チェック）

**依存パッケージはインストールしない。** torch / anomalib / scikit-learn / psutil が
未導入の状態で、構文検査・テスト・`--help`・安全性チェックだけを実行する。
`tests/` 側は重い依存を関数内で遅延 import し、未導入時は `unittest.SkipTest` で
スキップする構成にしてある（素の venv で全テストが完走し、一部が skip される。
Issue #8 時点の確認値は依存なしの venv で 104 tests OK / skipped 13）。

外部データセットや学習済み重みを CI で取得しない理由は次のとおり。

- 配布元の状態・ネットワーク・認証に CI の合否が左右されないようにする。
- MVTec AD などは非商用などの利用条件があり、CI で自動取得して扱うべきではない。
- CPU のみの環境では学習・評価に時間がかかり（例: PatchCore bottle の学習は約 280 秒）、
  データ取得も含めると 10 分の timeout に収まらない。CI は「軽い壊れ検知」に役割を絞る。

そのため CI は、モデルの精度やベンチマーク数値が正しいことを保証しない。
保証するのは「依存なしでも import・構文・CLI 引数定義が壊れていないこと」と
「追跡ファイルに危険なものが混ざっていないこと」である。

## 2. 実データを使う長時間検証（CI の外）

MVTec AD など実データを使う学習・評価は CI では実行しない。手元で手動実行する。

1. データセットは配布元の指示に従って自分で取得し、**リポジトリの外**に置く。
2. 利用可能な引数を確認する。

   ```sh
   python scripts/run_anomalib.py --help
   ```

3. データセットのルートや出力先はスクリプトの引数で指定する（引数名は `--help` を
   参照）。出力先もリポジトリ外にするか、後述の要約のみを残す。
4. 実行したら、結果を次の 2 か所に記録する。
   - `benchmarks/`: 実行条件と結果の**要約**（JSON / CSV）。相対パス・数値・設定のみを
     置き、画像・重み・ログ全文は置かない。既存の `benchmarks/issue7/manifests/*.json`
     と同じ方針。
   - `docs/verification/`: 実行日、実行環境（CPU・メモリ・Python / 主要パッケージの
     バージョン）、実行したコマンド、結果の要約と考察。再現に必要な情報を文章で残す。
5. 画像・重み・データセットそのものはコミットしない。`scripts/check_repo_safety.py`
   が拡張子とサイズで検出する。

数値は実測したものだけを書き、未検証の値や推定値を実測値として書かない。

## 3. 第三者データ・重みの権利とライセンス確認

データセットや事前学習済み重みは、コード（MIT）とは別のライセンスで配布されている。
利用・公開の前に次を確認する。

### 既知の注意点

- **MVTec AD**: CC BY-NC-SA 4.0（**非商用**、表示、継承）。本リポジトリでは
  画像・派生データを再配布せず、Git 管理しない。ライセンス名と出典を文書に明記する。
- **MVTec-4K**: 配布ページには Apache-2.0 の表記があるが、派生元の権利・利用条件も
  併せて確認する。表記が 1 か所だけの場合は、配布ページ全体と同梱の LICENSE を読む。
- **torchvision / timm の事前学習済み重み**: 重みごとにモデルカードがあり、学習に
  使われたデータ（ImageNet など）の利用条件も関係する。重みの再配布可否と、
  学習データ側の条件を分けて確認する。

いずれも「リポジトリに含めるのはコード・設定・要約数値だけ」を原則とする。

### 確認手順チェックリスト

- [ ] 配布元の URL と取得日を控えた
- [ ] ライセンス表記を原文で読み、名称と要点を `docs/verification/` に転記した
- [ ] 商用利用の可否を確認した
- [ ] 再配布の可否を確認した（不可なら Git 管理しない）
- [ ] 派生物・改変物の条件（ShareAlike、表示義務など）を確認した
- [ ] 重みの場合、学習データ側の利用条件も確認した
- [ ] リポジトリに入れるものがコード・設定・要約数値だけであることを確認した
- [ ] 判断に迷う場合は公開せず保留し、確認できるまでコミットしない

## 4. コミット前チェック

追跡ファイル全体の検査は CI でも実行するが、コミット前に手元で確認すると事故が減る。

```sh
python scripts/check_repo_safety.py --staged
```

`--staged` は `git diff --cached --name-only -z --diff-filter=ACMR` の対象
（追加・コピー・変更・リネーム）を検査する。終了コードは違反なしで 0、違反ありで 1。
検出時は一致した値そのものを出力せず、ファイル名・行番号・規則名だけを表示する。

任意で pre-commit フックに登録する。フックは `.git/hooks/` 配下にあり
**Git 管理されない**ため、clone ごとに一度だけ設定する。

```sh
#!/bin/sh
# .git/hooks/pre-commit
python scripts/check_repo_safety.py --staged || {
  echo "コミットを中止しました。scripts/check_repo_safety.py の指摘を確認してください。" >&2
  exit 1
}
```

```sh
chmod +x .git/hooks/pre-commit
```

### 検査内容

| 規則名 | 内容 | 既定値・例外 |
| --- | --- | --- |
| `size` | 1 ファイルのサイズ上限 | 1 MiB（`--max-bytes` で変更） |
| `extension` | モデル重み・アーカイブの拡張子 | 画像は `docs/images/` 配下のみ許可 |
| `directory` | 禁止ディレクトリ接頭辞 | `datasets/` `results/` `artifacts/` `checkpoints/` |
| `secret` | 秘密情報らしき文字列 | UTF-8 として読めるファイルのみ対象 |

`secret` の対象は、秘密鍵ブロック、AWS アクセスキー ID、GitHub トークン、
OpenAI 風の API キー、Slack トークン、`api_key = "..."` 形式の代入など。
パターンに当てはまらない形式の秘密情報は検出できないため、このチェックは
「よくある事故を減らす補助」であり、レビューの代わりにはならない。
